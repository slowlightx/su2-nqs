## Branches replace experimental copies, not immutable job releases

Use one repository, with `main` for reviewed code, a protected `production` or `production/<campaign>` pointer for approved releases, and short-lived `feature/<topic>` branches. A branch is a cheap reference to commits; normal sequential development can use one checkout. Concurrent agents or different running code revisions cannot safely share a checkout while switching branches. The current history begins with the audited import snapshot; do not invent historical commits or pretend a current-tree commit reproduces an older global45 job. Preserve old sealed manifests and their actual archived source.

Each Slurm submission must lock the **full code commit SHA**, config SHA, environment/container or package versions, input checkpoint SHA, scientific RNG/optimizer identity and job/run ID in its manifest. Resolve the branch before submission: the job must not execute `git pull`, follow a mutable branch, or import from an editable development checkout.

On the cluster, maintain one Git object store/clone and **one detached release/worktree per distinct concurrently needed SHA**, not a full data-bearing copy for every experiment. Jobs on the same SHA may share read-only source. Alternatively deploy a verified code-only archive/bundle from that SHA when Git is unavailable. Keep checkpoints, datasets, output directories and caches in independent immutable artifact/run storage; pass absolute paths or an explicit artifact root. Existing scripts that assume source-relative results need an explicit deployment mapping before this layout is used.

Do not switch branches, overwrite code, or garbage-collect a release used by a running allocation. Existing remote sealed workspaces remain untouched until their jobs have completed and the parent-state/source receipts are retained. Hardlinks are acceptable only for **immutable** same-filesystem artifacts with no in-place writer; never hardlink mutable development source to a supposedly frozen job tree. Code-only bundles or shared Git objects avoid copying checkpoint data without that hazard.
